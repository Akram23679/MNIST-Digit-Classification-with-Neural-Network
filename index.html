01 / project brief

Teach a computer to read handwritten digits.

Handwritten digit recognition powers cheque processing, postcode sorting and form digitisation. This project builds a CNN that classifies 28×28 greyscale images into the digits 0–9, with a clean validation strategy and a pipeline for testing real-world images.

Project goalsScope
  • Accuracy: reach above 99.5% on the untouched MNIST test set.
  • Robustness: use augmentation so the model copes with rotated, shifted and resized digits.
  • Sound evaluation: keep a separate validation split so the test set is used only once.
  • Real use: preprocess uploaded photos and screenshots so they match MNIST style.
Improvements over a basic notebookEngineering
  • Validation split for model selection, so no test-set leakage.
  • Augmentation inside the model: runs on the GPU and switches off automatically at inference.
  • Early stopping and checkpointing both watch val_loss, so the saved model is the best one.
  • Fixed random seed for reproducible results.
02 / data and method

70,000 digits, split three ways.

MNIST contains 28×28 greyscale images of handwritten digits. The official 60,000 training images were split 90/10 with stratification into training and validation sets. The 10,000 test images were held back for one final evaluation.

Preprocessing and augmentationInputs
  • Scaling: pixel values from 0–255 to 0–1, reshaped to (28, 28, 1).
  • Labels: one-hot encoded into 10 classes.
  • Augmentation: random rotation (±10°), zoom (±10%) and translation (±10%), applied only during training.
  • Input pipeline: tf.data with shuffling, batches of 128 and prefetching.
Training setupPipeline
  • Optimiser: Adam, learning rate 0.001; categorical cross-entropy loss.
  • ReduceLROnPlateau: halves the learning rate after 4 epochs without improvement.
  • EarlyStopping: patience 8, restoring the best weights.
  • ModelCheckpoint: saves the model with the lowest validation loss.
  • Hardware: Google Colab T4 GPU, about 10 seconds per epoch.
03 / model architecture

Two convolution blocks, one dense head.

Each block stacks two 3×3 convolutions with batch normalisation and ReLU, then halves the image size with max pooling and applies dropout. A 256-unit dense layer with heavy dropout feeds a 10-way softmax.

Why this designRationale
  • Stacked 3×3 convolutions learn strokes, then curves and loops, with few parameters.
  • Batch normalisation stabilises training and allows faster learning.
  • Dropout (0.25 and 0.5) and augmentation fight overfitting.
  • The dense layer holds 92% of the weights; the convolution blocks do the feature extraction with under 66K.

06 / findings

What the model learned, and where it slips.

Findings come from the notebook's test-set evaluation and from testing the model on real screenshots.

99.60%

Near-human accuracy

Only 40 of 10,000 test digits were misread. Test loss (0.0109) was even lower than validation loss, so the model generalises well.

9 → 4

The most common mistake

Five 9s were read as 4s, the single largest error. Open-topped 9s look like 4s. Next come 5s read as 3s (three cases).

99.21%

Digit 9 is the hardest

9 has the lowest recall (99.21%), mostly lost to 4. Yet when the model predicts 9 it is right 99.90% of the time, tied with 0 for the highest precision.

+

Augmentation prevents overfitting

Validation accuracy (99.48%) matched or beat training accuracy (99.44%) at the end, so the model is not memorising the training data.

99.98%

Works on real images

A screenshot of a single handwritten 7 was classified correctly with 99.98% confidence after MNIST-style preprocessing.

54.7%

One digit at a time

An image containing five digits ("12345") gave a low-confidence guess of 2. The model expects one centred digit, so multi-digit images need segmenting first.

07 / limitations and next steps

Where to take the model next.

MNIST is clean and centred. Real-world handwriting is messier, so these are the main gaps to close.

Limitations
  • Classifies one digit per image; multi-digit numbers need segmentation first.
  • MNIST digits are clean, centred and size-normalised; photos with noise or uneven lighting are harder.
  • The model always picks a digit, even for letters or blank scribbles.
  • The live demo runs a copy retrained with the same notebook code.
Suggested next steps
  • Add digit segmentation (e.g. contour detection) to read whole numbers.
  • Train on EMNIST or real handwriting samples for wider robustness.
  • Add a confidence threshold that returns "not sure" for unclear inputs.
  • Compress the model (pruning, quantisation) for mobile and edge devices.
